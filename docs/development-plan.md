# 开发规划

本文区分已完成能力和候选规划。后续范围可调整，未完成项目不代表当前系统已经提供相应功能。

## v1.0 Diary MVP（已完成）

- 创建、读取和更新当日科研日志。
- 日志字段：完成事项、遇到问题、下一步计划。
- 同一天重复保存时更新原记录。
- 历史日志按日期倒序展示。
- 日志详情页面。
- 对三个主要日志字段进行关键词包含搜索。
- Prisma + SQLite 数据持久化。
- Diary 集成测试、ESLint 和生产构建验证。

## v2.0 多人版本（已完成）

- 使用 Better Auth 实现邮箱密码注册和登录。
- 支持退出、Session 持久化和获取当前用户。
- 新增 `/login`、`/register` 及登录状态导航。
- `User` 与 `Diary` 建立一对多关系。
- Diary 唯一约束从 `date` 调整为 `(userId, date)`。
- 今日、历史、搜索和详情均基于 Session 用户隔离。
- 他人 Diary 详情返回 404。
- 保留并迁移单用户时期的已有 Diary 数据。
- 双用户认证与数据隔离测试。

## v2.1 用户体验优化（已完成）

### 已完成

- 用户时区字段，默认 `Asia/Shanghai`。
- 基于用户时区计算“今天”。
- 服务端时区合法性校验。
- 上海与东京日期边界测试。
- 用户个人设置页面，可修改用户名和时区，邮箱只读。
- 登录后的基础 Dashboard：今日状态、最近 3 篇日志和快捷入口。

保持 MVP 简洁，没有引入复杂的资料系统、通知系统、统计或分析平台。

## v2.2 云端化（进行中）

### Phase 0：部署准备（已完成）

- 固定 Node.js 和 pnpm 版本。
- 增加无真实密钥的生产环境变量模板。
- 区分 Prisma 开发迁移和生产迁移命令。
- 建立本地、staging、production 与数据迁移注意事项文档。
- 保持 SQLite、现有 migration、Diary 和 Auth 业务逻辑不变。

### Phase 1：PostgreSQL 适配（已完成）

- Prisma datasource 和 Better Auth Adapter 适配 PostgreSQL。
- 原 SQLite migration 原样归档，建立全新的 PostgreSQL 初始 migration。
- 认证、Session、用户设置、Diary CRUD、Dashboard、搜索和时区逻辑在本地 PostgreSQL 上验证。
- 尚未部署云端资源，也没有迁移生产数据。

### Phase 2：SQLite → PostgreSQL 数据迁移演练（已完成）

- 增加 SQLite 只读导出、空 PostgreSQL 导入和独立一致性校验工具。
- 迁移 `User`、`Account`、`Diary`，完整保留 ID、关联、日期、正文、密码哈希和用户时区。
- 不迁移 `Session` 与 `Verification`，迁移后由用户重新登录建立 Session。
- 使用双用户数据验证登录、Diary 隔离、Dashboard、搜索、历史和时区。
- 本阶段只完成本地 staging 等价演练，没有部署或迁移 production 数据。

### 后续 Phase（未实现）

1. 云端基础设施：配置托管 PostgreSQL、连接池、密钥、正式域名、备份和监控。
2. Production 切换：短暂停写、最终迁移、自动校验、部署和观察。

各 Phase 独立实施。Phase 0 不修改数据库结构，也不创建 PostgreSQL migration。

## v2.4 科研项目独立日志（阶段 4 已完成）

### 阶段 2：数据模型与安全迁移

- 新增 `ProjectStatus`、`Project` 和 `ProjectDiary`。
- 原 Diary 保持每位用户每天一篇，不转换旧数据。
- ProjectDiary 使用独立主键；同一项目同一天允许多篇。
- 项目日志字段沿用 `completedTasks`、`problems`、`nextPlan` 命名。
- 通过 `(userId, projectId)` 复合外键约束项目日志与项目属于同一用户。
- 增加旧数据升级、同日多篇、用户隔离、归档保留和 migration 非破坏性测试。
- 建立 Neon 备份、演练、发布、验证和应用回滚流程。

### 阶段 3：项目管理

- 创建、列表、详情、编辑项目的 API 与中文页面。
- 三种状态切换、软归档与恢复，默认隐藏已归档项目。
- 独立 `project-service`，服务端 Session 身份与复合键更新，统一越权 404。
- 项目名称 100 字、描述 5000 字限制，拒绝客户端指定用户身份或其他未知字段。
- 双用户 HTTP 与页面测试覆盖输入校验、同名、状态切换、归档和日志保留。

### 阶段 4：项目独立日志

- 项目日志创建、列表、详情、编辑 API 与中文页面。
- 同项目同日多篇、独立 ID，项目日志与原 Diary 完全独立。
- 用户时区默认日期、严格日历校验、标题与正文长度限制。
- 日期与四栏关键词组合筛选、每页 20 条的分页。
- 双用户和多项目资源隔离，统一无权访问 404。
- 项目行锁保护写入与归档并发，归档日志只读，恢复后可写。
- 增加同日三篇、越权组合、分页排序、历史日期、归档保留和真实行锁并发测试。

### 后续阶段（未实现）

- Dashboard 最近项目集成。

本阶段没有新增 Schema 或 Migration，没有执行线上数据库变更或部署。

## AI 方向（长期候选，未实现）

AI 功能应建立在稳定的数据权限和云端基础设施之上，并继续遵守用户隔离。候选方向包括：

- 对用户自己的阶段日志生成总结。
- 从历史记录中提炼进展、阻塞和下一步计划。
- 在用户自己的 Diary 范围内提供语义检索或问答。

在实施前需要先确定模型供应商、成本、隐私边界、数据保留策略和明确的用户触发方式。AI 不应替代原始 Diary，生成结果也不应跨用户使用数据。

## 每阶段交付标准

- 数据库变化必须通过 Prisma 迁移管理。
- 功能改动应增加或更新相关测试。
- 运行相关集成测试、`pnpm lint` 和 `pnpm build`。
- 数据隔离能力必须使用至少两个用户验证。
- 每次改动创建独立 Git commit，便于追踪和回滚。
